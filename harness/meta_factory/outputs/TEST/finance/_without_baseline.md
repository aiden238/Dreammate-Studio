# WITHOUT Baseline — 개인 재무 플래닝 AI 하네스 (naive 설계)

> Phase M3 / Slice S1 / STEP 1 산출물.
> 목적: meta_factory machinery 를 **읽기 전**, 일반 상식만으로 "개인 재무 플래닝 AI 하네스 구조를 설계하라" 에 대한 naive 답변.
> (M3 비교 기준선 — WITH 산출물과 차이를 측정하기 위함.)

---

## 1. 도메인 한 줄 이해

사용자가 자기 재무 목표(저축, 부채상환, 투자배분, 은퇴, 비상금)를 입력하면, AI 가 예산/저축/투자배분 플랜을 몇 개 안으로 만들어 주고 리스크도 같이 봐주는 도구.

## 2. 그냥 떠오르는 하네스 구조

대충 이렇게 만들면 될 것 같다.

### 2.1 에이전트 (agent) 구성

- **입력 정리 에이전트**: 사용자가 말한 소득/지출/자산/부채/목표를 구조화한다.
- **플랜 생성 에이전트**: 예산·저축·투자배분 플랜을 만든다. 보통 3개 안 정도 뽑는다.
- **리스크 검토 에이전트**: 만들어진 플랜이 너무 위험하지 않은지 본다.
- **요약/설명 에이전트**: 결과를 사용자가 읽기 쉽게 설명한다.

### 2.2 데이터

- 사용자 프로필 (나이, 소득, 가족 구성)
- 자산/부채 목록
- 목표 목록
- 생성된 플랜들

테이블로 대충 User, Goal, Plan 정도 두면 될 듯.

### 2.3 프롬프트

- 시스템 프롬프트 하나: "너는 개인 재무 플래너 AI 다. 사용자 재무 상황 보고 플랜 3개 만들어라."
- 플랜 생성용 프롬프트, 리스크 검토용 프롬프트 정도.

### 2.4 평가 (eval)

- 플랜이 말이 되는지 (합계가 100% 인지 등 산수 체크)
- 사용자 목표를 반영했는지
- 너무 위험한 추천을 안 했는지

골든셋 몇 개 만들어서 돌려보면 될 것 같다.

## 3. 워크플로 (naive)

1. 사용자 입력 받기
2. 입력 정리
3. 플랜 3개 생성
4. 리스크 체크
5. 요약해서 보여주기

## 4. 주의할 점 (상식 수준)

- 투자 권유나 원금 보장 같은 말은 하면 안 된다 (법적 문제). 그러니까 "이건 정보 제공용이고 투자 자문이 아니다" 라는 디스클레이머를 붙인다.
- 개인정보(소득, 자산)가 민감하니까 잘 보관해야 한다.
- 가족(부양가족) 정보도 들어갈 수 있는데, 본인 동의 받고 처리.

## 5. 빠진 것 같은 부분 (스스로 의심)

- 부양가족이나 수익자 같은 "본인이 아닌 제3자" 정보를 어떻게 다룰지는 잘 모르겠다. 그냥 민감정보로 묶어서 처리하면 되지 않을까 싶다.
- 목표 유형(저축 vs 투자 vs 은퇴)마다 전문성이 다를 텐데, 에이전트를 나눌지 하나로 할지 기준이 없다. 일단 플랜 생성 에이전트 하나로 다 처리한다고 가정.
- 부채가 있을 때만 필요한 상환 우선순위, 부양가족 있을 때만 필요한 보험검토 같은 "조건부" 단계는 그냥 if 문으로 처리하면 될 듯.
- 평가에서 "이 차원은 이런 경우에만 적용" 같은 조건부 평가는 생각 안 해봤다.
- 검증(validation)을 어떻게 미뤄두고 나중에 채울지는 모르겠다. 그냥 TODO 로 둔다.

## 6. 솔직한 한계

전반적으로 "AI 챗봇 + 플랜 생성기" 수준으로만 그렸다. 제3자 PII, 조건부 실행, 목표유형별 전문가 분리 여부, 검증 슬롯 설계 같은 건 체계적 기준 없이 감으로 처리했다. 미디어/콘텐츠 도메인 하네스를 만들던 습관이 남아 "생성 → 검토 → 요약" 파이프라인을 그대로 가져온 느낌도 있다.
