## 3. 회귀 안전 근거 (behavior-preserving)

- **default mock 불변 ★**: `run_golden_set_eval()` 기본 호출은 Phase 9.5 와 동일 mock-deterministic
  경로 (`_mock_envelope_for_case` → `score_case`). 채점/임계값/리포트 로직 0 변경. mock eval-run
  결과는 phase-9.5_baseline 대비 schema/pass/gate/revise effect 전부 동일 (GS-012~015 추가분만 신규 pass).
- **실 LLM 호출 0 ★**: real 경로는 `ScoreContext.llm_caller` 주입 + 키 존재 시에만 활성. 본 모듈은
  실 LLM client 를 import 하지 않으며 default caller 가 없어 단독 실 호출 불가. CI/test 는
  caller 미주입(또는 stub) → `resolve_mode` 가 항상 mock 반환 → 실 API/네트워크 0. 키는 user-provided
  `.env` (저장소 placeholder 만, 키 commit 0).
- **golden_set additive ★**: GS-001~011 (id/input/expected_*) 무변경. GS-012~015 는 신규 추가만.
  loader 는 케이스 수 무관 GS-XXX 파싱 (ADR-033 §2.1) → 확대 시 코드 변경 0.
- **RAG rubric additive ★**: `rag_eval_rubric.md` 신규 문서. `rag/eval_rubric.py` 3 dim 구현 무변경 —
  rubric §1.A 가 구현 정합을 문서화하고, §1.B 검색 차원은 golden_set GS-007/GS-014 가 단일 출처.
- **의도 delta (문서화)**:
  1. golden_set count 단언 11→15 (`test_load_golden_set_15_cases` / priority P0 7·P1 6·P2 2 / mock total 15).
  2. `mode='real'` 동작 NotImplementedError → graceful mock fallback (capability wire). 신규 test 로 검증.
