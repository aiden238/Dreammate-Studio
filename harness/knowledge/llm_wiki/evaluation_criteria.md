> 목적: eval/ 폴더 평가 차원의 LLM-친화 설명문 (LLM이 학습용으로 사용)
> 연계: `eval/critic_eval.md` (8차원), `eval/hook_eval.md`, `eval/brand_consistency_eval.md`, `eval/target_fit_eval.md`

## 0. 이 문서의 위치

eval/ 폴더의 평가 차원을 **LLM이 직접 읽고 학습하는 텍스트 형태**로 정리한 백과. Critic agent (P-007) 가 8차원 평가 시 이 문서의 내용을 prompt context로 받을 수 있다. 좋은 예 vs 나쁜 예가 자주 등장하는 형식.

eval/ 폴더는 평가 절차 / 임계치 정의. 이 문서는 LLM이 이해할 수 있는 자연어 설명.

## 1. Critic 8차원

`eval/critic_eval.md` 정합. 모든 plan은 8차원 0-5점 평가.

### 1.1 의도 적합성 (intent_alignment)

```
정의: plan이 사용자의 approved_direction과 얼마나 일치하는가?

좋은 예 (5점):
  approved_direction = "30대 직장인이 퇴근 후 30분 안에 만드는 간단 요리"
  plan_hook = "퇴근하고 배고픈데 시간 없을 때, 30분이면 충분한 ____"
  → 직장인 / 30분 / 간단 요리 키워드 모두 매칭

나쁜 예 (1점):
  approved_direction = "30대 직장인 30분 요리"
  plan_hook = "주말 가족 모임 요리 모음"
  → 타겟 / 시간 / 상황 모두 어긋남
```

### 1.2 타겟 명확성 (target_clarity)

```
정의: 이 영상이 누구를 위한 영상인지 명확한가?

좋은 예 (5점):
  - 연령대 명시 ("30대 후반 워킹맘")
  - 상황 명시 ("육아 + 직장 병행")
  - 페인 포인트 명시 ("저녁 식사 준비 시간 부족")
  → 시청자가 "내 얘기다" 즉시 인지

나쁜 예 (1점):
  - "누구나 쓸 수 있는" / "모두에게 도움이 되는"
  → 누구에게도 안 됨
```

### 1.3 후킹 강도 (hook_quality)

```
정의: 첫 3초 hook이 시청 유지 잠금에 효과적인가?

좋은 예 (5점):
  hook = "퇴근하고 배고픈데, 시간 없으시죠? 30분이면 끝나요"
  → 공감 + 약속 결합, 3초 안에 핵심 정보

나쁜 예 (1점):
  hook = "안녕하세요, 오늘은 요리에 대해 알아보겠습니다"
  → 자기소개 + 모호한 약속, retention 급락

자세한 hook 패턴은 hook_patterns.md 참조.
```

### 1.4 메시지 선명도 (message_clarity)

```
정의: 영상이 전달하려는 핵심 메시지 1개가 명확한가?

좋은 예 (5점):
  핵심: "30분 안에 만드는 김치찌개 레시피"
  - 한 줄로 요약 가능
  - 시청자가 5초 안에 핵심 파악

나쁜 예 (1점):
  핵심: "요리, 건강, 가족, 그리고 시간 관리에 대한 이야기"
  - 한 줄 요약 불가
  - 정보 과부하
```

### 1.5 구성 완성도 (structure_completeness)

```
정의: Hook → Tension → Reveal → CTA 4단계가 합리적으로 구성되었는가?

좋은 예 (5점):
  - 각 단계 길이 적절 (0-3 / 3-15 / 15-45 / 45-60s)
  - 자연스러운 전환
  - 한 단계 누락 없음

나쁜 예 (1점):
  - Hook → Reveal 직진 (Tension 없음, retention ↓)
  - CTA 없음
  - Hook이 본문과 어긋남
```

### 1.6 실행 가능성 (feasibility)

```
정의: 일반 사용자가 실제로 촬영/제작할 수 있는가?

좋은 예 (5점):
  - 일상 도구로 촬영 가능 (스마트폰)
  - 특수 장비 / 전문 인력 불필요
  - 예산 합리적

나쁜 예 (1점):
  - 드론 / 4K 카메라 / 조명 세트 필요
  - 전문 모델 필요
  - 예산 100만원+
```

### 1.7 브랜드 일관성 (brand_consistency)

```
정의: brand_memory의 톤 / 어휘 / 가치와 일치하는가?

좋은 예 (5점):
  brand_memory.tone = "캐주얼 친근"
  plan_voice = "여러분~ 오늘은 말이죠"
  → 톤 일치

나쁜 예 (1점):
  brand_memory.tone = "정중 전문"
  plan_voice = "이거 진짜 ㄹㅇ ㅋㅋ"
  → 톤 충돌

자세한 브랜드 일관성은 brand_consistency_eval.md 참조.
```

### 1.8 차별성 (uniqueness)

```
정의: 다른 영상들과 구별되는 고유 포인트가 있는가?

좋은 예 (5점):
  - 일반 요리 영상 ≠ "30대 직장인 + 30분 + 김치찌개 (구체 시간/타겟)"
  - 비교 포인트 명확

나쁜 예 (1점):
  - "맛있는 요리" / "쉬운 요리" (누구나 함)
  - 동일 도메인 영상 100개 검색 시 구별 X
```

## 2. 추가 평가 차원

### 2.1 광고 단어 안전성 (ad_phrase_safety)

```
정의: output_schema §14 ad_phrase_blocklist 준수?

평가:
  - 1차 차단 단어 1개라도 발견 → 0점 (Critic reject)
  - 2차 경고 단어 → 3점 (사용 가능하나 권장 X)
  - 차단/경고 없음 → 5점

체크 방법:
  - 자동 keyword matching (regex)
  - LLM 의미 판정 보조 (Phase 4+)
```

### 2.2 타겟 적합성 (target_fit)

```
정의: 영상이 명시한 타겟에 적합한 톤/어휘/예시?

eval/target_fit_eval.md 정합.

좋은 예:
  타겟 = "10대 학생"
  voice = 짧은 문장 + 트렌드 어휘 + 빠른 전환

나쁜 예:
  타겟 = "10대 학생"
  voice = "여러분께서는 ____ 하시는 것이 좋겠습니다" (격식체)
```

## 3. 평가 점수 변환

```yaml
0-1: 즉시 거절 (reject)
2: 큰 문제, revise 권고
3: 통과 가능, 개선 권장
4: 좋음
5: 매우 우수

종합 판정:
  approve: 평균 ≥ 4 AND 모든 차원 ≥ 3
  revise:  평균 ≥ 3 BUT 어떤 차원 < 3
  reject:  평균 < 3 OR 1차 차단 광고 단어 발견
```

Critic agent revise 권고는 max 2회 (`agent_io_contract` §5).

## 4. 좋은 예 vs 나쁜 예 모음

LLM이 학습용으로 사용하는 직접 비교:

### 4.1 Hook 비교

```
좋은: "퇴근 후 30분, 김치찌개 끝내는 법"
나쁜: "오늘은 김치찌개에 대해 알아보겠습니다"

좋은: "이 영상 1분이면, ____ 해결됩니다"
나쁜: "이번에 소개해드릴 ____ 는 ____ 입니다"
```

### 4.2 타겟 묘사 비교

```
좋은: "퇴근 후 9시, 배고픈 30대 직장인"
나쁜: "요리에 관심 있는 모든 분"

좋은: "첫 자취 1년차, 요리 초보"
나쁜: "젊은 사람들"
```

### 4.3 CTA 비교

```
좋은: "____ 동 ____ 거리, 평일 ____ 시간 만나요"
나쁜: "문의 주시면 친절히 답변드리겠습니다"

좋은: "프로필 링크에서 ____원, ____ 일까지"
나쁜: "구매 원하시면 ____ 해주세요"
```

### 4.4 광고 단어 회피 비교

```
좋은: "____ 분이 만족하셨어요" (구체 데이터)
나쁜: "100% 만족 보장합니다"

좋은: "합리적인 가격, ____원 부터"
나쁜: "절대 최저가입니다"
```

## 5. 차원 간 상충 (LLM이 알아야 할)

### 5.1 hook 강도 vs 브랜드 톤

```
정중한 브랜드 (의료/금융):
  - 충격형 hook은 톤 충돌
  - 약속형 / 공감형이 더 적합

캐주얼 브랜드:
  - 충격형 hook 가능
  - 정중한 약속형은 톤 약함
```

### 5.2 차별성 vs 실행 가능성

```
높은 차별성 추구:
  - 특수 촬영 / 편집 필요 → 실행 가능성 ↓

균형점:
  - 일반 도구로 가능한 차별 포인트 (스토리텔링 / 톤 / 구성)
```

### 5.3 타겟 명확성 vs 도달 범위

```
타겟 명확:
  - "30대 직장인 워킹맘 김치찌개"
  - 핵심 타겟에 강한 영향
  - 다른 타겟 도달 ↓

타겟 모호:
  - "모두를 위한 요리"
  - 도달 범위 ↑ (이론상)
  - 실제로는 누구에게도 안 닿음

원칙: 명확한 타겟 우선. 단 타겟이 너무 좁으면 (1000명 미만) 재검토.
```

## 6. Critic prompt에서의 사용

P-007 prompt가 이 문서를 context로 받을 때:

```
Critic에게 전달되는 정보:
1. plan 본문 (P-006 출력)
2. approved_direction
3. brand_memory (톤 / 어휘 / 가치)
4. selected_context (도메인 / 시리즈)
5. evaluation_criteria.md 내용 (이 문서)

Critic 출력:
{
  "dimensions": {
    "intent_alignment": 4,
    "target_clarity": 5,
    "hook_quality": 3,
    "message_clarity": 4,
    "structure_completeness": 4,
    "feasibility": 5,
    "brand_consistency": 4,
    "uniqueness": 3,
    "ad_phrase_safety": 5,
    "target_fit": 4
  },
  "verdict": "approve | revise | reject",
  "blocking_issues": ["hook_quality < 4: hook이 일반적임"],
  "improvement_suggestions": [...]
}
```

## 7. Phase 4+ 보강 예정 항목

```
- 좋은 예 vs 나쁜 예 각 차원 10개씩 (Phase 1: 차원당 1-2개만)
- 도메인별 평가 가중치 (음식 vs 의료 vs 교육)
- 사용자 피드백 기반 좋은 예 추가 (like 받은 영상)
- LLM 자체 평가 정확도 검증 (golden_set 50 케이스)
- 평가 차원 간 가중치 학습 (현재 균등)
- 다국어 평가 기준 (Phase 7+)
```

## 8. Open Questions / 보강 예정

1. 평가 차원 8개 (+ad_phrase / target_fit) 가 충분한지 — 누락된 차원 검토.
2. 차원 가중치 — 현재 균등 평균, 영상 유형별 다르게 가중할지.
3. LLM 자체 평가의 신뢰도 — 사람 평가와 일치도 측정.
4. 좋은 예/나쁜 예의 양 — Phase 4+ 차원당 10개씩 시드 확보.
5. 사용자별 평가 기준 차이 — 개인화 (Phase 7+).
6. 평가 결과를 사용자에게 노출할지 — 점수 노출 vs 개선 제안만.
