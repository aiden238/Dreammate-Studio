# multi-llm-validation

같은 입력에 다른 LLM이 다르게 답하면 그게 곧 신호다. 일치하면 신뢰도 ↑, 불일치하면 그 부분이 검토 대상.

## 트리거 조건

- 큰 설계 결정 (UX 패러다임, 데이터 계층, 아키텍처)
- 중요한 contract 변경 검토
- prompt-version-review의 major bump
- 사용자 본인이 "다른 모델한테도 물어봐줘"
- 회고에서 단일 모델 편향 의심
- 보안 / 비용 critical 결정 직전

### 필수 정량 임계 (HIP-004 — 2026-06-05)

★ 다음 중 **1개라도** 해당하면 multi-llm-validation **필수**(주관 판단 불요). HIP-006 텔레메트리로 비용 데이터원이 확보되어 정량화됨 (`meta/harness_improvement_proposals.md` HIP-004 승인):

```
- 영향 파일 ≥ 5개 (한 변경이 5+ 파일 수정)
- prompt major version bump (P-XXX vN.0.0 — prompt-version-review 연동)
- 가격 / 보안 / 영구 제외(mvp_non_goals) 변경
- cost-review(observability/cost_report, agent_io 텔레메트리 집계) 월 추정 비용 임계 초과
```

위 외에는 본 §트리거 조건의 질적 기준 + 사용자 판단.

## 사용하지 않는 경우

```
- 사소한 코드 수정
- 명확한 사실 질문
- 단순 산출물 (잘 정의된 변환 작업)
- 시간 민감하지 않은 일상 작업
```

비용/시간이 1.5–3배 들어가므로 가치 명확할 때만.

## 절차

### 1. 검증 목적 명시

이 검증으로 답해야 하는 질문 1개를 한 문장으로:

```
✅ 좋은 검증 질문
- "Discovery vs Quick 하이브리드 UX가 4계층 데이터 모델과 정합한가?"
- "이 prompt가 광고적 표현 검출에서 false negative가 얼마나 발생할까?"
- "이 보안 정책에 빠진 공격 surface가 있나?"

❌ 나쁜 검증 질문
- "이 디자인 어때?" (너무 광범위)
- "코드 짜줘" (검증이 아니라 생성)
```

### 2. 컨텍스트 패키징

각 모델에 보낼 컨텍스트를 통일된 형태로 묶음:

```
## Validation Context Package

### Question
{검증 질문 1문장}

### Background
{프로젝트/도메인 배경 5–10줄}

### Decision under review
{검토 대상 결정 또는 산출물}

### Constraints
{지킬 제약: MVP 범위, 4계층, 모바일 우선 등}

### Evaluation criteria
{어떤 기준으로 평가해주길 원하는지}

### Output format
{원하는 응답 형식: 점수표, 근거, 대안}
```

### 3. 모델 선택

기본 3-tuple: **Claude, GPT-5, Gemini Pro**.

추가/대체 가능:

```
설계/추론 강도     : Claude Opus, GPT-5, Gemini Pro
코드 검토          : Claude, GPT-5, Codex
요약/정리          : Haiku, GPT-5 mini, Gemini Flash (저비용 모드)
한국어 뉘앙스      : Claude, GPT-5, HyperCLOVA
```

특수 검증:
- 보안 검증 시 보수적 모델 추가 (Claude with Constitutional AI 강조)
- 비용 검증 시 모델 자체의 비용 계산 능력 차이 고려

### 4. 호출 순서

```
방식 A: 병렬
- 3개 모델에 동시 발송
- 서로의 답을 모름 (독립성 우선)
- 최종 종합은 사용자 또는 4번째 모델
- 권장 기본값

방식 B: 순차 + 익명화
- 첫 모델에게 묻고 답 받음
- 다음 모델에 "이전 답을 익명으로 첨부, 비판해줘"
- 답 누적
- 편향 누적 가능성, 신중히 사용

방식 C: 토론
- 모델 A, B가 서로 비판 라운드 N회
- 최종 합의 또는 불일치 지점 도출
- 비용 큼, 정말 중요한 결정에만
```

### 5. 응답 정리

각 모델 응답을 통일된 표로:

```
| 차원 | Claude | GPT-5 | Gemini | 일치도 |
|---|---|---|---|---|
| 핵심 결론 | ... | ... | ... | 3/3 |
| 주요 근거 | ... | ... | ... | 부분 |
| 우려 사항 | ... | ... | ... | 1/3 |
| 대안 제시 | ... | ... | ... | 0/3 |
| 신뢰도 (자체 평가) | 0.8 | 0.7 | 0.85 | - |
```

### 6. 합의 / 불일치 분석

```
합의 사항 (3/3 일치):
- {모델 모두 동의한 점}
→ 신뢰도 높음, 결정 근거로 사용

다수 의견 (2/3):
- {다수가 동의했지만 한 모델 이견}
→ 이견 모델의 근거 검토. 무시할지, 추가 검토할지.

불일치 (각자 다른 결론):
- {세 모델이 다 다른 답}
→ 질문이 모호하거나, 정말 어려운 결정. 추가 정보 필요.
```

### 7. 결과 종합

종합 방식:

```
A. 사용자가 직접 종합
   - 표를 보고 결정 (가장 일반적)

B. 4번째 모델 (메타 모델)에 종합 위임
   - 컨텍스트 + 3개 응답 → 종합 응답
   - "어느 모델 말이 맞는지" 판정 아니라 "각 의견의 강점/약점" 분석
   - 메타 모델은 보통 Claude 또는 GPT-5

C. 합의 부분만 채택
   - 3/3 일치 항목만 결정에 사용
   - 불일치는 추가 검증 또는 보수적 선택
```

## 모델별 강점/약점 (현재 기준)

빠르게 모델 선택 시 참고:

```
Claude (Opus/Sonnet)
+ 긴 컨텍스트 일관성, 윤리/안전, 한국어 자연스러움
- 보수적, 종종 거절

GPT-5
+ 코드, 도구 사용, 빠른 응답
- 일관성 변동, hallucination 가능

Gemini Pro
+ 멀티모달, 사실 확인 (Search 연동)
- 한국어 뉘앙스 약함, 형식 깨짐

Haiku / GPT-5 mini / Gemini Flash
+ 저비용, 빠름
- 깊은 추론 약함, 큰 결정엔 부적합
```

이 표는 분기 1회 회고 시 갱신.

## 자주 발생하는 실수

1. **컨텍스트 패키지 모델마다 다르게**: 비교 불가. 항상 통일.
2. **순차 방식 + 익명화 누락**: 뒷 모델이 앞 모델 답 따라감.
3. **자체 신뢰도만 보고 결정**: 모든 모델이 자기 답을 자신함. 합의도가 진짜 신호.
4. **불일치 무시**: 가장 가치 있는 정보 (검토 깊이 필요한 지점) 놓침.
5. **모든 결정에 multi-LLM**: 비용 폭증. 가치 큰 결정만.
6. **결과 기록 안 함**: 다음에 비슷한 결정 시 재발명.

## 다른 Skill과의 관계

```
contract-change        : 큰 변경 시 검증 후 제안서 첨부
prompt-version-review  : major bump 시 검증
design-review          : 중요한 UX 패러다임 결정 시
security-review        : 보안 critical 결정 시
meta-retrospective     : 단일 모델 편향이 회고에서 발견되면 트리거
```

## 종료 조건

- 결과 종합 + 결정 + 기록 완료 → 정상 종료
- 합의 강한 결과 → 그대로 결정 반영
- 강한 불일치 → 추가 정보 수집 후 재검증 또는 보수적 선택 후 종료
- 비용 초과 우려 → 저비용 모드(작은 모델 3개)로 전환
