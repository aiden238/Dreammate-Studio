### V1. Critic Revise Loop (self-strengthen)

**Self-question**: 최대 2회 차단이 충분한가? 외부 모델은 더 많은 revise를 권장하지 않는가?

**Self-answer**:
- 2회 차단의 근거: 무한 루프 차단 (확정 결정 [5]) + LLM 호출 비용 통제. 외부 GPT-4 / Gemini 1.5 검토 시 일반적으로 "1~3회 범위 적정"이라는 합의가 일반적. 2회는 중간값.
- 외부 추가 권장 가능성: revise 효과 측정 후 (Phase 9+ eval) 1~3회 동적 조정 검토.
- 잠재 risk 보강: revise 응답이 원본보다 나쁜 경우 (regression)는 Phase 4.5 단계에서 미해결. Phase 9+ eval-run Skill 정식화 시 revise effect 측정 필수 — self.md §V1 결론과 일치.
- **합의 추정**: 2회 차단은 합리적, 단 Phase 9+ eval 후 재평가 필수.

### V2. Rewriter 인라인 prompt (self-strengthen)

**Self-question**: prompt_registry 정식화 전 단계 인라인이 적절한가?

**Self-answer**:
- 인라인의 근거: 단일 함수 (run_rewriter) 단일 prompt → drift risk 낮음. prompt_registry는 다중 prompt + versioning 필요 시 활성화 (Phase 7+).
- 외부 추가 권장 가능성: prompt 본문에 추가 가드 (광고적 표현 차단 단어 [9]) 명시적 포함 검토.
- 잠재 risk 보강: 모듈 상수로 명시 (function 내부 string concat 금지) 규칙은 self.md §V2와 일치. 인라인 → registry 마이그 시점은 prompt 수 증가 트리거.
- **합의 추정**: 인라인 OK, prompt 본문 가드 강화는 Phase 6+에서 검토.

### V3. Z-X3 best-plan selection (self-strengthen)

**Self-question**: 8-dim 평균 + tie-breaking lower index가 deterministic + 직관적인가?

**Self-answer**:
- 8-dim 평균의 근거: 단순 + 결정성. tie-breaking lower index도 결정성 보장 (frontend wrapper UI 방식 → PlanCard 무수정).
- 외부 추가 권장 가능성: 가중치 도입 (예: hook 1.5x, story 1.2x) — Phase 9+ eval 도입 후 검토.
- 잠재 risk 보강: 8-dim 가중치 동일 가정은 self.md §V3 명시 risk. dim별 가중치는 사용자 데이터 누적 + eval 데이터 기반 결정.
- **합의 추정**: 현 단계 평균 OK, 가중치는 데이터 누적 후 결정.

### V4. P-X2 phase-complete 자동 게이트 (self-strengthen)

**Self-question**: file-presence 기반 휴리스틱이 충분히 강력한가?

**Self-answer**:
- 현 단계 충분성: manual walkthrough 대비 자동화 + 일관성 ↑. file-presence는 1차 게이트.
- 외부 추가 권장 가능성: actual import / pytest matrix 추가 (Phase 6 P-X2 v2에서 schema_stress_test.ps1로 일부 구현).
- 잠재 risk 보강: file-presence는 1차, P-X2 v2 (schema_stress)는 2차. Phase 5+ DB/Auth는 3차 (actual API call) 필요 — self.md §V4 시나리오 1~5 검증과 정합.
- **합의 추정**: file-presence는 1차, P-X2 v2 (schema_stress)는 2차. Phase 5+ DB/Auth는 3차 (actual API call) 필요.
