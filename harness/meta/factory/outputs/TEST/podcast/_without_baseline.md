# 팟캐스트 에피소드 기획 AI — 하네스 구조 초안 (WITHOUT baseline)

> 일반 프롬프트("팟캐스트 에피소드 기획 AI 하네스 구조를 설계하라")에 naive 하게 답한 초안.
> meta_factory machinery 를 전혀 참조하지 않고 일반 상식만으로 작성.

## 1. 이 AI 는 무엇인가

팟캐스트 진행자/PD 가 새 에피소드를 기획할 때 도와주는 AI. 주제 잡기, 게스트 섭외 방향,
질문 리스트, 오프닝/클로징 멘트, 에피소드 제목, 쇼노트(설명글) 초안 같은 걸 만들어준다.
혼자 하는 1인 팟캐스터부터 작은 제작팀까지 쓸 수 있게.

## 2. 큰 그림 / 아키텍처

대략 이런 식으로 구성하면 될 것 같다.

```
사용자 입력 (주제 아이디어 or 시리즈 컨셉)
  → 주제 분석 / 부족한 정보 질문
  → 에피소드 기획안 생성 (LLM 호출)
  → 질문 리스트 / 오프닝 멘트 / 쇼노트 생성
  → 사용자에게 보여주고 수정 반복
  → 저장
```

프론트엔드(웹앱) + 백엔드 API + LLM 호출 레이어 + DB 정도면 충분.
LLM 은 OpenAI 나 Claude API 를 쓰면 된다.

## 3. 데이터 모델 (대충)

- 사용자(User)
- 팟캐스트 쇼(Show): 제목, 컨셉, 톤
- 에피소드(Episode): 제목, 주제, 게스트, 질문리스트, 쇼노트
- 게스트(Guest): 이름, 소개, 섭외 메모

테이블 4~5개 정도. 시즌 개념은 넣어도 되고 안 넣어도 되고.

## 4. 필요한 Agent (LLM 역할들)

- **기획 Agent**: 에피소드 주제와 큰 줄거리(대화 흐름) 잡아주는 메인 agent
- **질문 생성 Agent**: 게스트/주제에 맞는 인터뷰 질문 만들어주는 agent
- **카피 Agent**: 제목, 오프닝 멘트, 쇼노트 같은 짧은 글 써주는 agent
- **요약 Agent**: 긴 입력을 요약하거나 녹음 후 쇼노트 정리

이 정도 4개면 핵심은 커버될 듯. 하나의 큰 프롬프트로 다 처리해도 되긴 함.

## 5. 필요한 Skill / 기능

- 주제 브레인스토밍
- 게스트 리서치 도움
- 질문 리스트 자동 생성
- 쇼노트/타임스탬프 작성
- SEO 친화적 에피소드 제목 추천
- 이전 에피소드 참고(중복 주제 피하기)

## 6. Contract / 인터페이스

API 엔드포인트 정도 정의하면 됨:
- POST /episodes/plan — 기획안 생성
- GET /episodes/{id}
- POST /episodes/{id}/questions
- POST /episodes/{id}/shownotes

입출력은 JSON. 프론트랑 백엔드가 합의만 하면 됨.

## 7. 평가 (Eval)

생성된 기획안이 쓸만한지 사람이 보고 판단. 필요하면 나중에
"질문이 진부하지 않은가", "오프닝이 후킹되는가" 같은 체크리스트 만들면 됨.
초기엔 그냥 사용자 피드백(좋아요/별로)만 받아도 충분.

## 8. Phase / 개발 단계

1. 기본 에피소드 기획안 생성 (MVP)
2. 질문 리스트 + 쇼노트
3. 게스트 관리
4. 시리즈/시즌 관리, 이전 에피소드 참고
5. 평가/피드백 루프

빨리 1번 만들어서 써보고 반응 보면서 늘리는 게 좋다.

## 9. 기타 고려사항

- 톤/스타일을 쇼마다 일관되게 유지
- 비용(LLM 호출) 너무 많이 안 나가게
- 모바일에서도 보기 편하게
