본 Slice의 **최우선 acceptance**: 어떤 RAG 실패 경로에서도 사용자 요청을 차단하지 않는다.

| 실패 시나리오 | 검증 테스트 | fallback_reason | router 응답 |
|---|---|---|---|
| pgvector env 미설정 | `test_retrieval_env_missing` | `env_missing` | 200 OK + 빈 references |
| pgvector 연결 실패 (timeout / refused) | `test_retrieval_connection_error` | `pgvector_unreachable` | 200 OK + 빈 references |
| embedding 호출 실패 (OPENAI_API_KEY 없음) | (retriever 내부 `_embed_query → None`) | `query_error` | 200 OK + 빈 references |
| 검색 결과 모두 threshold 미통과 | (retriever 내부 `_rows_to_references → []`) | `empty_result` | 200 OK + 빈 references |
| router 내부 예외 (방어 try/except) | (router catch-all) | `pgvector_unreachable` (방어 default) | 200 OK + 빈 references |

**핵심 보장**: 어떤 경로에서도 HTTP 500/502 발생 안 함. RAG 실패는 항상 validation.checks의
`rag_retrieval status="warn"` + detail 필드로 관측 가능하되 사용자 응답은 정상 200.
