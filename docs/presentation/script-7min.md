## 0:00 – 1:00 — 문제 정의 + 한 줄 가치 제안

> (표지 슬라이드. 천천히, 또박또박.)

안녕하세요. 저는 **영상기획 AI 에이전트 Dreammate Studio**를 만들고 있습니다.

먼저 분명히 하면, 이건 **영상을 만들어주는 도구가 아니라, 영상을 만들기 "전"의 기획을 도와주는 에이전트**입니다.

영상 제작 도구는 이미 많습니다. CapCut, Runway처럼요. 정작 부족한 건 **"무엇을, 누구에게, 어떻게 말할지"를 정하는 기획의 품질**입니다. 1인 마케터나 소규모 브랜드는 영상 한 편 기획에 2~4시간이 걸리고, 브랜드 톤을 일관되게 유지하기도 어렵습니다.

그래서 한 줄 가치 제안은 이렇습니다.
> **"막연한 영상 아이디어를, 브랜드 방향·타깃·메시지·기획안·실행계획(WBS)까지 연결한다."**

그리고 중요한 차별점 하나 — 저희는 "범용 LLM보다 잘 만든다"고 주장하지 않습니다. 실제로 실험해보니 일반 품질 차이는 작았습니다. 진짜 강점은 **"쓸수록 내 브랜드에 맞춰지는" 개인화**입니다. 이 부분은 뒤에서 수치로 보여드리겠습니다.

## 1:00 – 2:00 — 사용자 시나리오 1개

> (문제·비전 → 솔루션 흐름 슬라이드)

실제 사용자 김지영 씨, 1인 향수 브랜드 마케터를 예로 들겠습니다.

처음 가입하면 브랜드 정보가 없으니 **Discovery 위저드**가 5단계 카드로 안내합니다. 브랜드 등록 → 도메인(뷰티) → 시리즈(신상 리뷰) → 타깃(20대 향수 입문자) → 톤(친근 후기형). 각 단계는 AI 추천 4개 + 직접 입력 1개 카드로 보여주니, 빈 입력창 앞에서 막막할 일이 없습니다.

정보가 모이면 AI가 **"한 줄 기획 방향"을 제안하고 사용자가 승인**합니다. 승인하면 30~60초 안에 **기획안 후보 3개**가 나오고, 사용자가 하나를 고르고 피드백을 남기면 그게 **다음 기획에 반영**됩니다.

두 번째부터는 위저드를 다 거치지 않고 **Quick 모드** — 짧은 한 줄과 1~2개 질문만으로 끝납니다. 이미 쌓인 브랜드 컨텍스트를 재사용하기 때문입니다.

핵심은 — **매번 처음부터가 아니라, 누적된 내 지식 위에서 기획한다**는 것입니다.

## 2:00 – 3:30 — 아키텍처 / 기술 스택 (왜 선택했는지)

> (아키텍처 슬라이드 — 소프트웨어 아키텍처 + AI 파이프라인 도식)

구조는 크게 두 축입니다.

**(1) 소프트웨어 아키텍처**
- **프론트: Next.js 14 PWA** — 모바일 마케터가 주 타깃이라 설치 없이 모바일 친화적으로 쓸 수 있고, 빠른 반복 개발이 가능해서 선택했습니다.
- **백엔드: FastAPI (Python)** — AI/LLM 생태계가 Python 중심이라 에이전트·RAG 코드와 한 언어로 묶었습니다.
- **데이터: Supabase (PostgreSQL + pgvector)** — Auth, DB, 벡터 검색(RAG)을 한 곳에서 해결해 1인 개발 부담을 줄였습니다.
- **LLM: 기본 gpt-4o-mini, 검증만 상위 모델** — 비용 때문입니다. 생성은 싼 모델로 많이, 품질 검증(Critic)만 비싼 모델로.

**(2) AI 에이전트 파이프라인 — MOA Lite**
단일 LLM 호출이 아니라 역할을 나눴습니다:
> Intent(분기) → RAG(근거검색) → Planning(후보 3개 생성) → **Critic(품질 평가, 최대 2회 재작성)** → 저장 + Memory.

Critic이 기획안을 평가하고 부족하면 다시 쓰게 하되, **무한 루프를 막으려고 재작성을 2회로 제한**했습니다. 또 OpenAI·Claude·Gemini 3사를 추상화한 **LLM Gateway**를 둬서 모델을 바꿔 끼울 수 있게 했습니다.

이 모든 결정은 문서(ADR)로 남겨 두었습니다. "왜 이렇게 했나"를 추적할 수 있습니다.

## 3:30 – 5:30 — 현재 진행 상황 + 데모 ★

> (WBS 대시보드 슬라이드 — 이 구간이 핵심, 2분 확보)

현재 진행률부터 정직하게 말씀드리면 — **"코드 완성도는 높고, 실사용 운영은 중간, 품질 검증은 약함"**입니다. 이게 저희 프로젝트의 자체 진단이고, 대시보드에도 그대로 적었습니다.

**완료된 것:**
- 핵심 파이프라인 전부 — Intent, RAG 5단계, Planning, Critic 재작성, 3-provider Gateway.
- 회원가입·로그인(JWT 쿠키), 4계층 데이터 모델, 피드백·메모리.
- **테스트 814개 통과**, API 30개, PWA 14개 라우트.

**그리고 가장 중요한 — 라이브로 검증했습니다:**
> 실제 OpenAI 모델로 **연출 깊이(director) 기획안 3개를 생성**하고, **Supabase에 저장해 재시작해도 남는 것**까지 확인했습니다. (PASS)

(여기서 대시보드의 라이브 PASS 증거 / 스크린샷 / 30초 영상 재생)

**솔직한 한계도 말씀드립니다:**
- 만들어 둔 핵심 기능 다수가 안전을 위해 **기본 OFF**라, 평소엔 잘 안 보입니다. 그래서 이번에 **"실사용 프로파일" 단일 스위치**로 한 번에 켜지도록 마감했습니다.
- **프론트 화면 완성도는 아직 테스트 수준**이라, "진짜 에이전트 같은" UX로 끌어올리는 게 다음 작업입니다.

> (프론트 라이브 데모를 한다면 이 자리. 안 되면 영상/스크린샷으로 대체하고 다음으로.)

## 발표 운영 체크 (당일)

1. PC에서 GitHub Pages URL을 먼저 띄워 둔다 (cold start 회피).
2. **30초~1분 데모 백업 영상**을 미리 열어 둔다.
3. 알림 끄기 / 전체 화면 / 타이머 7분.
4. 라이브 데모 실패 시: "이 부분은 영상으로 보여드리겠습니다" 하고 즉시 전환.
5. 모르는 질문: "그 부분은 정확히 모릅니다. 확인해서 알려드리겠습니다" — 거짓 답변보다 +점수.
