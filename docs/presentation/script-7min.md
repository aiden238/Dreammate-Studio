## ⏱ 0:00 – 1:00 — 문제 정의 + 한 줄 가치 제안
*(표지 → 문제·비전 슬라이드)*

안녕하세요. 저는 영상기획 AI 에이전트, **Dreammate Studio**를 만들고 있는 [발표자 이름]입니다.

시작하기 전에 한 가지만 분명히 하겠습니다. 이 프로젝트는 영상을 **대신 만들어주는 도구가 아닙니다.** 영상을 만들기 "전" 단계, 그러니까 **기획**을 도와주는 에이전트입니다.

생각해보면 영상을 편집하고 제작하는 도구는 이미 충분히 많습니다. 캡컷이나 런웨이 같은 것들이죠. 그런데 정작 부족한 건, **"무엇을, 누구에게, 어떻게 말할지"를 정하는 기획의 품질**입니다. 실제로 1인 마케터나 작은 브랜드는 영상 한 편 기획하는 데에만 두세 시간이 걸리고, 브랜드 톤을 일관되게 유지하기도 어렵습니다.

그래서 저희의 가치 제안을 한 줄로 요약하면 이렇습니다. **"막연한 영상 아이디어를, 브랜드 방향·타깃·메시지·기획안, 그리고 실행 계획인 WBS까지 한 번에 연결한다."**

그리고 미리 핵심 차별점 하나만 말씀드리면 — 저희는 "범용 AI보다 더 잘 만든다"고 주장하지 않습니다. 진짜 강점은 **"쓸수록 내 브랜드에 맞춰진다"**는 개인화에 있고, 이건 뒤에서 수치로 보여드리겠습니다.

## ⏱ 1:00 – 2:00 — 사용자 시나리오
*(솔루션 흐름 슬라이드)*

실제로 어떻게 쓰는지, 1인 향수 브랜드 마케터 "김지영" 씨를 예로 들어 보겠습니다.

지영 씨가 처음 가입하면 아직 브랜드 정보가 없겠죠. 그러면 **Discovery 위저드**가 다섯 단계 카드로 안내합니다. 브랜드를 등록하고, 도메인은 뷰티, 시리즈는 신상 리뷰, 타깃은 20대 향수 입문자, 톤은 친근한 후기형. 이런 식으로요. 각 단계마다 **AI 추천 카드 네 개와 직접 입력 한 개**를 보여주기 때문에, 빈 입력창 앞에서 막막해질 일이 없습니다.

정보가 모이면 AI가 **"한 줄 기획 방향"을 제안하고, 사용자가 그걸 승인**합니다. 승인하면 30초에서 1분 안에 **기획안 후보 세 개**가 나오고, 그중 하나를 고르고 피드백을 남기면 그 선택이 **다음 기획에 반영**됩니다.

그래서 두 번째 사용부터는 이 위저드를 다 거치지 않습니다. **Quick 모드**로, 짧은 한 줄과 한두 개 질문이면 끝납니다. 이미 쌓인 브랜드 컨텍스트를 다시 쓰기 때문이죠.

핵심은 이겁니다. **매번 처음부터가 아니라, 누적된 내 지식 위에서 기획한다.**

## ⏱ 2:00 – 3:30 — 기술 스택과 아키텍처 (왜 이렇게 선택했나)
*(아키텍처 슬라이드 — 소프트웨어 구조 + AI 파이프라인 도식)*

이제 구조와 기술 선택을 설명드리겠습니다. 크게 두 축입니다.

먼저 **소프트웨어 아키텍처**입니다. 프론트엔드는 **Next.js 기반 PWA**로 만들었습니다. 주 사용자가 모바일 마케터라서, 설치 없이 모바일에서 바로 쓸 수 있고 개발도 빠르게 반복할 수 있기 때문입니다. 백엔드는 **FastAPI, 파이썬**입니다. AI와 RAG 생태계가 파이썬 중심이라, 에이전트 코드와 API를 한 언어로 묶어 복잡도를 줄였습니다. 데이터는 **Supabase**를 썼는데, 인증과 데이터베이스, 그리고 벡터 검색까지 한 곳에서 해결돼서 1인 개발 부담이 크게 줄었습니다. LLM은 **기본은 저렴한 모델로 생성을 많이 하고, 품질 검증만 상위 모델**로 돌립니다. 비용 때문입니다.

두 번째 축은 **AI 에이전트 파이프라인**, 저희가 MOA Lite라고 부르는 구조입니다. 단일 AI 호출이 아니라 역할을 나눴습니다. 입력을 분석하고, 근거를 검색하고, 기획안 세 개를 만들고, 그다음 **Critic 에이전트가 품질을 평가해서 부족하면 다시 쓰게 합니다.** 단, 무한 루프를 막으려고 **재작성은 최대 두 번**으로 제한했습니다. 그리고 OpenAI, Claude, Gemini 세 모델을 추상화한 **게이트웨이**를 둬서, 모델을 갈아 끼울 수 있게 했습니다.

이 모든 결정은 **ADR 문서로 기록**해서, "왜 이렇게 했는지"를 나중에도 추적할 수 있습니다.

## ⏱ 3:30 – 5:30 — 현재 진행 상황 + 데모 ★
*(WBS 대시보드 슬라이드 — 이 구간이 핵심, 2분)*

현재 진행 상황을 **정직하게** 말씀드리겠습니다. 저희 프로젝트의 자체 진단은 **"코드 완성도는 높고, 실사용 운영은 중간, 품질 검증은 약하다"**입니다. 이 문장을 대시보드에도 그대로 적어 뒀습니다.

먼저 **완료된 것**입니다. 핵심 파이프라인은 전부 동작합니다. 의도 분석, RAG 5단계, 기획안 생성, Critic 재작성, 그리고 3사 모델 게이트웨이까지요. 회원가입과 로그인, 4계층 데이터 모델, 피드백과 메모리도 들어가 있습니다. 수치로는 **테스트 814개 통과, API 30개, 화면 14개**입니다.

그리고 가장 중요한 건 — **실제로 라이브 검증을 했다**는 점입니다.
*(대시보드의 라이브 PASS 증거 / 스크린샷 / 30초 영상 재생)*
실제 OpenAI 모델로 **연출 깊이의 기획안 세 개를 생성**하고, 그걸 **Supabase에 저장해서 서버를 재시작해도 남아 있는 것**까지 확인했습니다. 통과했습니다.

이제 **솔직한 한계**도 말씀드리겠습니다. 만들어 둔 핵심 기능들이 안전을 위해 **기본적으로 꺼져 있어서**, 평소에는 잘 안 보입니다. 그래서 이번에 **"실사용 프로파일"이라는 스위치 하나로 한꺼번에 켜지도록** 마감했습니다. 또 하나, **프론트엔드 화면 완성도는 아직 테스트 수준**입니다. "진짜 에이전트 같은" 사용자 경험으로 끌어올리는 게 바로 다음 작업입니다.

*(실 앱 라이브 데모를 한다면 여기서. 안 되면 영상·스크린샷으로 대체하고 넘어갑니다.)*

## ⏱ 5:30 – 6:30 — 남은 일정과 우선순위
*(남은 일정 슬라이드)*

남은 일정은 순서가 명확합니다.

가장 먼저 할 일은 **프론트엔드를 "에이전트답게" 시각적으로 고도화**하는 것입니다. 그다음은 **실제 사용자 5명에서 10명에게 써보게 하는 실-런 검증**, 그리고 여기서 핵심은 **사람이 직접 기획안 품질을 채점**하는 것입니다. 그 이후에 **2차 MVP와 배포 단계** — 요청량 제한이나 운영 인프라 같은 것들 — 로 넘어갑니다.

한 가지 더 보강할 게 있다면 **테스트 자동화 CI**입니다. 지금은 발표 사이트 배포만 자동화돼 있고, 테스트는 로컬에서 돌리고 있어서, 이걸 GitHub Actions에 올리는 게 우선순위 높은 과제입니다.

우선순위를 정하는 원칙은 하나입니다. **"코드는 됐으니, 이제 진짜 사람이 써보고 품질을 검증한다."** 자동 테스트가 통과해도 실제로는 동작하지 않을 수 있다는 걸 이번에 직접 겪었기 때문입니다.

## 📋 발표 운영 체크 (당일 — 말하지 않는 메모)

1. PC에서 GitHub Pages URL을 미리 띄워 둔다 (cold start 회피).
2. **30초~1분 데모 백업 영상**을 미리 열어 둔다.
3. 알림 끄기 / 전체 화면 / 타이머 7분.
4. 라이브 데모 실패 시: "이 부분은 영상으로 보여드리겠습니다" 하고 즉시 전환.
5. 모르는 질문: "그 부분은 정확히 모릅니다. 확인해서 알려드리겠습니다." — 거짓 답변보다 +점수.
