## 0:15 – 0:45 · 비전 (슬라이드: 비전)
`[채점] 체계성 — (1)비전 표현 (1)비전을 와닿게 표현`

(비전 슬라이드로 이동)
저희가 그리는 그림은 이렇습니다. **영상은 '한 편'이 아니라 '브랜드'로 쌓여야 합니다.**
유튜브에 영상 하나 잘 만드는 건 누구나 할 수 있습니다. 하지만 영상 열 편을 만들어도 **브랜드가 남지 않으면** 그건 그냥 흩어진 콘텐츠일 뿐입니다.
그래서 Dreammate Studio의 비전은, 막연한 영상 아이디어를 **브랜드 방향, 타깃, 메시지, 기획안, 그리고 실행 WBS까지** 하나의 흐름으로 연결하는 겁니다.
세 가지를 약속합니다 — **브랜드로 축적되고, 질문으로 구조화되고, 실행까지 연결된다.**

`[채점] 체계성 — (1)문제정의 표현 (1)문제정의 공감대`

(문제정의 슬라이드로 이동)
그럼 왜 이게 필요할까요? **영상은 많이 만들수록, 오히려 브랜드는 더 흐려집니다.**
현장에서 세 가지 문제가 반복됩니다. 첫째, **브랜드 방향이 불명확**해서 영상마다 톤이 흔들립니다. 둘째, **타깃이 모호**해서 누구에게 각인될지 메시지가 약합니다. 셋째, 전략이 있어도 **촬영·편집·업로드로 분해되지 않아 실행이 멈춥니다.**
한마디로 — **"기획 없이 만든 영상은 조회수는 나와도 브랜드는 남지 않는다."** 이게 저희가 풀려는 문제입니다.

## 1:15 – 1:45 · 해결 방식 (슬라이드: 해결)
`[채점] 체계성 — 해결 방식 제시`

(해결 슬라이드로 이동)
해결책은 **질문형 AI**입니다.
사용자가 "쇼츠 만들고 싶어요" 한 줄만 입력하면, AI가 **브랜드 → 타깃 → 레퍼런스** 순서로 질문하며 방향을 좁힙니다. 그다음 영상 기획안을 **세 개 동시에** 만들고, **Critic 에이전트가 품질을 검증·개선**한 뒤, 선택된 안을 **실행 WBS로 전환**합니다.
중요한 차별점 — 저희는 영상을 **'만들어' 주지 않습니다.** 무엇을, 왜, 누구에게 만들지를 **'정해' 줍니다.** 영상 제작·편집·자동 업로드는 의도적으로 범위 밖에 뒀습니다.

## 1:45 – 2:10 · 기술 스택 + WBS (슬라이드: 기술·WBS → WBS)
`[채점] 체계성 — (1)적용 기술 표현 (1)WBS 표현/구성 충족`

(기술 슬라이드)
적용 기술입니다. 프론트는 **Next.js 14 PWA**, 백엔드는 **FastAPI**, 데이터는 **Supabase의 PostgreSQL과 pgvector**, LLM은 **OpenAI gpt-4o 계열**, 검색 근거는 **pgvector RAG**로 구성했습니다. 색상은 인디고–시안 **브랜드 컬러보드**로 슬라이드·앱·PPT를 통일했습니다.
(WBS 슬라이드로 이동)
일정은 WBS로 관리했고, **Phase 0번부터 31번까지 완료**했습니다. 테스트는 **845개가 자동으로 통과**하고, 의사결정은 **ADR 39건**으로 기록했습니다.

## 2:10 – 2:35 · 아키텍처 (슬라이드: 아키텍처)
`[채점] 기본소양 — 아키텍처 이해 설명 / 질의응답 — 앱 구조`

(아키텍처 슬라이드로 이동)
구조는 **명확한 4계층**입니다. 사용자가 **Next.js PWA**로 입력하면, **FastAPI**가 인증·요청·진행률을 처리하고, **AI 엔진**이 기획과 검증을 수행한 뒤, 결과는 **Supabase**에 행 수준 보안(RLS)으로 저장됩니다.
AI 내부는 **Route → Retrieve → Generate+Review → Save** 파이프라인입니다. 입력을 분기하고, 근거를 검색하고, 3안을 생성·평가·개선하고, 저장하면서 다음 기획에 반영합니다. 디렉토리도 이 레이어 그대로 `apps/web`, `backend`, `ai_system`으로 나눠 둬서 구조와 코드가 일치합니다.

## 2:35 – 3:00 · 구현 방법 (슬라이드: 구현)
`[채점] 체계성 — 어떻게 구현했는지 / 기본소양 — 구현 설명`

(구현 슬라이드로 이동)
어떻게 구현했는지 핵심만 말씀드리면 —
**3안 병렬 생성**으로 선택지를 주고, **Critic + Rewriter 루프**가 점수 미달이면 **최대 2회까지** 자동으로 다시 씁니다. RAG는 아무 데이터나 넣지 않고 **후보 → 필터 → 평가 → 승인 → 승격, 5단계**를 거친 검증된 지식만 검색에 들어갑니다.
운영 중 가장 컸던 작업은 659줄짜리 거대 함수를 **243줄 오케스트레이터로 분해**하면서도 **출력이 한 바이트도 안 바뀌게** 한 겁니다. 그리고 모든 입출력은 **contract라는 단일 진실 소스**를 기준으로 하고, 벗어나면 테스트가 즉시 잡습니다.

개발자로서 가장 배운 두 가지 시행착오입니다.

교훈은 하나입니다 — **"좋아 보인다"가 아니라 '측정값'으로 판단한다.**

# ❓ 예상 질문 & 모범 답변 (질의응답 5점 대비)

> 답변은 **ADR(의사결정 기록) 기준**으로 합니다. 상세: `docs/grading/03_아키텍처_ADR.md`.

**Q1. 앱 구조(레이어·디렉토리)는?**
A. 4계층입니다 — Next.js PWA(프론트) → FastAPI BFF(백엔드) → AI Engine(파이프라인) → Supabase(데이터). 디렉토리도 `apps/web`, `backend`, `ai_system`, `docs/contracts`로 레이어와 1:1 매칭됩니다.

**Q2. 개발 환경은 어떻게 설정했나요?**
A. Node 20 / Python 3.11 기준이고, `.env`로 키를 주입합니다(저장소 미포함). FE는 `npm run dev`, BE는 `uvicorn`, DB는 Supabase 마이그레이션 0001~0007. 상세는 `docs/grading/04_setup_deploy_testing.md`.

**Q3. 빌드와 배포는 어떤 단계인가요?**
A. **빌드**는 산출물 생성 — FE `next build`, BE 패키징. **배포**는 환경 배치 — FE Vercel, BE Render, DB Supabase, 발표 덱은 GitHub Pages. 배포 게이트 A~G를 정의했고 현재 로컬 스모크(Gate A)는 통과, 운영 배포는 키·인프라 주입 단계입니다.

**Q4. ADR 3개만 말해보세요.**
A. ① **기술 스택** — Next.js/FastAPI/Supabase/OpenAI를 대안 비교로 선택. ② **Supabase + RLS** — JWT httpOnly + 행 수준 보안으로 사용자 격리. ③ **cross-provider judge** — 단일 모델 자기 과대평가를 다른 provider 검증으로 교정(오승인 10→0). (그 외 RAG 5단계 승격, MOA 동작보존 분해 등 39건)

**Q5. 테스트는 어떻게 하나요? (단위/통합)**
A. 단위는 pytest 845개(hermetic), 통합은 integration MVP + 시나리오 시뮬레이션 36/36이 자동 게이트로 동작합니다. 품질은 eval-run이 golden_set 회귀로 임계값 미달 시 작업을 차단합니다.

**Q6. 왜 영상을 직접 만들지 않나요?**
A. MVP 범위를 '기획'으로 좁히는 게 의도된 결정입니다(mvp_non_goals). 제작은 도구가 많지만, '무엇을 왜 만들지'를 정해주는 기획 단계가 비어 있다고 봤습니다.

**Q7. 성능/비용은?**
A. 3안은 병렬 호출, 대기는 SSE 부분 결과로 체감 단축, rate_limit로 비용 폭탄을 막습니다. 비용/지연은 cost-review·eval 차원으로 측정합니다.

**Q8. AI Agent/스킬을 실제로 어떻게 쓰나요?**
A. `.claude/skills`에 21개 스킬을 두고 키워드로 자동 트리거합니다. 예: contract 변경은 `contract-change`, 평가는 `eval-run`, Phase 종료는 `phase-complete`가 절차를 강제합니다.

**Q9. 혼자 개발인데 품질을 어떻게 보장하나요?**
A. contract 단일 진실 소스 + 자동 회귀 테스트 + multi-llm-validation(Claude·GPT·Gemini 교차검증)으로 단일 인력·단일 모델의 편향을 보완합니다.

**Q10. 최신 LLM 지식은 어떻게 관리하나요?**
A. `knowledge/llm_wiki`에 최신 LLM 기반 암묵지를 정리하고, RAG는 5단계 승격을 통과한 지식만 반영해 오염을 막습니다.
